- 감정 구성 전체 교체, 일기만 변경/비우기, 실제 내용이 같은 요청의 버전·시각 유지.
- KST 23:59:59/00:00:00, 잠금 대기 중 날짜 변경, 판정 후 자정 경과.
- 같은 버전의 동시 수정 충돌, 비활성 감정 보존/감소 규칙, 타인·과거 병 수정 거부.
- 8개 이상 보존, 과거 페이지 이동, 커서 기준 병 삭제 후 탐색, 사용자별 데이터 격리.
- 동시 구슬 추가에서 7개 초과 차단, 동시 되돌리기에서 서로 다른 구슬 제거.
- 같은 사람의 동시 좋아요로 반응/알림 중복 생성 방지, 취소 시 알림 삭제, 재좋아요 재알림 방지.
- 감정·일기 편집 후 좋아요와 알림의 ID/생성·읽음 시각 유지.
- 친구 해제·병 삭제·좋아요한 사람 탈퇴·병 주인 탈퇴와 좋아요의 동시 처리.
- 두 유형의 통합 알림·필터·커서, 최초 읽음 시각 보존, 타인의 알림 읽기 거부.
- 친구 요청을 읽어도 대기 요청 배지는 유지, 수락/거절 후 요청 알림 삭제.
- 좋아요 PUT/DELETE 합산 사용자별 60회/분, 같은 IP의 다른 사용자 한도 분리.
- SQL trigger로 알림 생성 실패와 감정 재생성 실패를 강제로 일으켜 전체 트랜잭션 롤백 확인.
- DB 오류에 포함된 일기 원문을 로그/응답으로 노출하지 않음.

강제 실패 테스트 두 건에서 예상한 500 응답과 분류용 로그가 발생한다. 테스트의 성공 조건은 변경 사항 전체가 롤백되고 원문이 노출되지 않는 것이다.

## 검증 중 발견하여 수정한 문제

1. PostgreSQL 세션 시간대가 Asia/Seoul이면 기존 되돌리기 SQL의 DATE/timestamp 비교가 일치하지 않을 수 있었다. `YYYY-MM-DD` 문자열의 명시적 `::date` 비교로 수정했다.
2. 병 ID의 NUL 등 잘못된 입력이 DB 오류가 되지 않도록 상세·수정·삭제·좋아요 ID를 검증한다.
3. OpenAPI 선택 입력 객체의 빈 `required` 배열은 규격에 맞지 않아 생략하도록 수정했다. 규격 검사와 예시 검증을 `npm test`에 포함했다.

## 환경과 범위

- Node.js 24.14.0, Prisma Client 6.19.3, PostgreSQL 16.14. 로컬 DB 세션 시간대 Asia/Seoul.
- 검증은 `127.0.0.1:55432`의 별도 `mongly_test`, `mongly_test_upgrade` DB에서 수행했다.
- 운영 DB, 사용자 계정, 배포 서버는 변경하지 않았다. 프론트 UI 구현·브라우저 시각 검수는 이번 백엔드 작업 범위가 아니다.
- 실제 운영 인프라의 연결 지연·동시 트래픽 부하 검증은 별도 배포 환경에서 수행해야 한다. 위 5,000행 검사는 조회 실행계획 확인이며 운영 부하 시험 결과는 아니다.

## 배포 전 확인할 사항

신규 migration은 `20260924000000_add_notes_likes_notifications`이다. 배포 절차는 [변경 안내](API_CHANGES_2026-09-24.md#7-배포와-롤백)를 따른다.

최종 테스트 DB와 Prisma schema의 차이를 읽기 전용으로 비교한 결과, 변경 전부터 존재한 **JarImage 테이블의 schema 누락**만 남아 있었다. 이번 migration은 그 테이블과 데이터를 보존한다. 자동 생성된 DROP TABLE을 적용하지 않는다.

기존 FIFO 서버로 단순 롤백하면 누적 기록을 삭제할 수 있다. 또한 새 migration 이후 구 서버가 친구 요청을 생성하면 통합 알림 행이 누락될 수 있으므로, 문서의 전체 쓰기 중단·진행 요청 종료·서버 전환 절차를 지킨다.
